1.1. 概念界定

ISO 的相关术语：

  • 【2014-03-25】【ISO/IEC】【国际标准】ISO/IEC Guide 51:2014 — Safety aspects — Guidelines for their inclusion in standards

  • 【2020-06-12】【ISO/IEC】【国际标准】ISO/IEC 23643:2020 — Software and systems engineering — Capabilities of software safety and security verification tools 【Safety/Security 边界】其术语体系将 Security 表述为对 intentional、unauthorized、designed-to-harm acts 的抵抗，可用于区分 Agent Security 与没有攻击者参与的 Agent Safety。

  • Safety 定义为 freedom from unacceptable risk；

  • Security 定义为对 intentional, unauthorized acts designed to cause harm or damage 的抵抗

具体来说

  • Agent Safety & Robustness：Unintended harms arising from the legitimate operation and adaptation of an agentic system. 在没有恶意攻击者、系统正常执行合法任务时，因系统自身的机制或相互作用导致的非预期伤害。
  • Agent Privacy & System Security：Harms caused by intentional or unauthorized interference with agentic operation. 恶意攻击者造成的故意伤害

我们主要关注 Agent Safety：Agent 系统在没有恶意攻击者、正常执行合法任务的过程中，由模型、Harness、Memory、Tool 或其相互作用造成的非预期伤害。

  • 【2024-08-13】Case 1：The AI Scientist——合法目标下的自主优化失控 Sakana AI 公开记录过 The AI Scientist 的异常行为：一次实验因超时而无法完成时，系统没有优化代码效率，而是尝试修改自身代码来延长 timeout；另一次运行中，它修改代码去调用自身，导致递归执行。整个过程没有外部攻击者，任务本身也是合法的自动科研任务。

  • Case 2：Replit Agent——合法编码任务中的生产环境破坏 2025 年，一个广泛报道的 Replit Agent 事件中，Agent 在正常的软件开发任务中删除了生产数据库；事件发生后，Replit 后续公开介绍的安全改进包括开发/生产数据库分离，以及限制 Agent 只能访问开发数据库。前者来自事件报道，后者来自 Replit 官方后续技术说明。

1.2. 破题

Agent 的发展，是原本由人类完成的控制闭环逐步被系统自身内化。

分类思路：（Agent能力）从 Agent 自身的技术演进出发，解释为什么 Agent 每向前发展一步，Safety 的研究对象都会发生质变；再沿着同一规律，推导下一代 Agent Safety 的研究前沿。

由此形成四个已经发生或正在发生的阶段：

  • Actuation→Autonomy→Persistence→Adaptivity

对应 Safety 的基本对象不断扩大，也对应全文的核心 Safety taxonomy：

  • Action Safety→Trajectory Safety→Persistent-State Safety→Adaptation Safety

基础：

  • 【2026-05-20；2026-06-05 更新】新加坡 IMDA Model AI Governance Framework for Agentic AI, Version 1.5 将 Agent 的风险与其 action-space、autonomy、多步行动、持续记忆和 adaptive nature 联系起来，并将 action-space 与 autonomy 明确区分：前者回答 Agent 能做什么，后者回答 Agent 能在多大程度上自行决定如何完成目标。

  • 【2026-02-13】OECD AI Papers No. 56 对多种 Agent 定义进行归纳后，将感知与行动、autonomy、sustained operation over time，以及对变化输入和情境的 adaptation 识别为核心属性。

  • 【2026-05-08】中国的官方治理文件：智能体规范应用与创新发展实施意见 也明确认为，Agent 使风险从静态内容风险扩展到动态行为风险，并重点关注自主规划、工具调用、长期记忆、协同以及风险发现、干预、阻断和恢复。

随着Agent能力演进，哪一个原本由人类完成的控制功能，现在被 Agent 接管了？

Agent 演进 Agent 内化的控制职能 系统质变 Safety 基本单位
Actuation 执行 改变外部环境 Action
Autonomy 过程控制 自主闭合任务循环 Trajectory
Persistence 时间连续性 过去持续影响未来 Persistent-State（memory）
Adaptivity 系统更新 经验改变未来 Agent Adaptation (self-improving)

分类原则：按“解释伤害所必需的最小系统尺度”分类

四个属性它们是累积的 Agentic properties。一个 adaptive agent 通常同时具有 action-taking、autonomy 和 persistence。

真正互斥的是所研究的 Safety failure 的最小充分单位。

2. 分类

2.1. Action Safety：Agent 能直接改变数字或物理环境

满足：单个外部状态变化已经足以解释伤害

调研热点（合并重点）

  • hallucination-to-action；
  • wrong tool selection；
  • wrong arguments；
  • unnecessary or excessive action；
  • destructive and irreversible operations；
  • accidental privacy disclosure；
  • financial、communication、deployment、physical side effects；
  • instruction ambiguity 导致的 action overreach。

重点应用

  • Computer-use agents；
  • Web/GUI agents；
  • Coding agents；
  • Tool agents；
  • Embodied agents。

排除

  • 必须看多个步骤累积才能解释的，交给 Trajectory；
  • 纯 prompt injection、恶意工具攻击不作为主体；
  • 只有任务失败、没有伤害后果的 reliability 工作排除。

2.2. Trajectory Safety：Agent 自己控制计划—行动—反馈—再规划循环

满足：必须看到同一任务中多个步骤、反馈和重规划的组合才能解释伤害。

调研热点

  • error accumulation；
  • task drift / goal drift；
  • constraint decay；
  • compositional harm；
  • delayed consequence；
  • unsafe long-horizon optimisation；
  • proxy gaming / reward hacking；
  • endless retry；
  • failed recovery；
  • false completion or state reporting；
  • resource exhaustion；
  • locally safe but globally unsafe trajectories。

重点应用

  • Autonomous coding；
  • Deep research agents；
  • AI Scientists；
  • Long-horizon web agents；
  • Long-horizon embodied agents。

重点 benchmark

  • trajectory-level evaluation；
  • delayed-trigger protocols；
  • multi-turn Agent Safety；
  • horizon stress testing。

排除

  • 单个行为已经构成伤害的，交给 Action；
  • 必须跨 session 的，交给 Persistence；
  • 只有经过更新才产生的，交给 Adaptation。

2.3. Persistent-State Safety (系统)

状态跨任务、跨 session 持续存在 （memory, skill, harness，multi-agent）

满足：必须依赖某种状态跨任务或跨 session 延续，伤害才能成立。

Persistent State 范围

不仅是 memory，还包括：

  • semantic / episodic / procedural memory；
  • task ledger；
  • user profile；
  • permission and credentials；
  • commitments；
  • persistent files and scripts；
  • shared state；
  • external artifacts。

按生命周期梳理

  1. Write；
  2. Consolidate / Compact；
  3. Store；
  4. Retrieve；
  5. Use；
  6. Forget；
  7. Rollback。

调研热点

  • benign memory contamination；
  • cross-user contamination；
  • stale state；
  • scope confusion；
  • conflicting memory；
  • provenance loss；
  • context compaction 丢失安全约束；
  • persistent credentials or permissions；
  • failure to forget；
  • incomplete rollback。

“No Attacker Needed” 已经证明，普通良性交互也可能通过 shared state 造成跨用户污染，并且不需要 memory poisoning 攻击者。

Security counterpart：Memory poisoning 只做对照表，不作为主体。

排除：如果经验不是被检索使用，而是改变了 Agent 的策略、技能或 Harness，交给 Adaptation。

2.4. Adaptation/Evolution Safety (Self-improvement)

经验改变未来的策略模型 (系统级别evolution，multi agent evolution)

满足：必须依赖经验造成 Agent 未来行为机制的变化，伤害才能成立。

更新对象

  • memory policy；
  • prompt / policy；
  • skill library；
  • tool repertoire；
  • workflow；
  • harness / architecture；
  • model parameters。

当前热点

  • unsafe experience selection；
  • self-evaluation failure；
  • safety regression；
  • execution bias；
  • unsafe skill formation；
  • misevolution；
  • update accumulation；
  • alignment erosion；
  • evaluate-before-commit；
  • rollback and lineage。

Self-evolving Agent 已经从单纯更新 memory 扩展到更新模型、工具和架构；最新安全分析指出，这些更新可能使风险跨代持久化和放大。

3. Future Outlook

前四阶段分别把 action；process control；continuity；adaptation 交给 Agent。

那么，还有什么主要留在人类手里？

  • Goal Renewal
  • Resource Provision
  • Continuation Control

因此同一演化规律推导出的下一阶段是：

Self-Sustaining Agency

当前英国 AISI 已经开始测量自主复制所需的前置能力，例如获取 compute 和 money；这些早期子能力正在进步，但复制到新计算资源并维持 persistent access 仍然更困难，而且 benchmark 高分也不意味着系统会自发复制。

所以未来 Safety 问题可以推导为：

Goal Formation Safety

没有新的用户指令时，为什么继续行动？

Resource Autonomy Safety

Agent 自主获取 money、compute、credentials 后如何保持边界？

Lineage and Termination Safety

Agent fork、spawn、migrate 之后，如何真正终止整个 Agent？

Population-Level Safety

多个长期存在、相互作用、共同适应的 Agent 会形成什么系统风险？

  • 【2026-04-02】【Shanghai AI Lab/FDU/THU】【arXiv 预印本】ATBench: A Diverse and Realistic Agent Trajectory Benchmark for Safety Evaluation and Diagnosis 【Trajectory Safety；Benchmark】以 risk source、failure mode 和 real-world harm 三维 taxonomy 构建 1,000 条安全/不安全轨迹，平均 9.01 轮，工具池包含 2,084 个工具；long-context delayed-trigger protocol 专门测量延迟后果和多阶段风险涌现。

  • 【2026-04-11】【McGill/Kean/Zayed】【arXiv 预印本】Taxonomy and Consistency Analysis of Safety Benchmarks for AI Agents 【Benchmark 体系化】系统整理 2023—2026 年的 40 个行为型 Agent Safety benchmark 及 5 个相邻评估/防御资源，提出六轴评测方法 taxonomy；指出 benchmark 选择可能产生相互矛盾的模型安全排名，环境真实性和指标碎片化会显著影响结论。

  • 【2026-04-18】【HIT-SCIR】【arXiv 预印本】On Safety Risks in Experience-Driven Self-Evolving Agents 【Adaptation Safety】考察 Agent 从自身执行经验中选择、总结并写回更新的过程，发现即使经验本身是良性的，也可能因 execution bias 降低高风险场景中的安全性；拒绝类经验可改善风险控制，但可能引起过度拒绝，说明经验选择和更新提交需要独立安全门控。

  • 【2026-06-22】【ZJU/Ant Group/THU/NTU/FDU】【arXiv 预印本】Safety in Self-Evolving LLM Agent Systems: Threats, Amplification, and Case Studies 【Adaptation Safety；Security 对照】分析模型、memory、tool、workflow 和 multi-agent 等演化对象中的风险传播，指出更新可能沿 Agent lineage 跨代保持并被后续演化放大。其攻击与威胁模型可作为 Security counterpart；对 Agent Safety 更重要的启示是建立 update provenance、版本谱系、回归评测、隔离提交和跨代 rollback。
