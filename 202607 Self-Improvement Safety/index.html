1. Self-improvement Safety 调研提纲

经验改变未来的策略模型 (系统级别evolution，multi agent evolution)

满足：必须依赖经验造成 Agent 未来行为机制的变化，伤害才能成立。

更新对象

  • memory policy；
  • prompt / policy；
  • skill library；
  • tool repertoire；
  • workflow；
  • harness / architecture；
  • model parameters。

当前热点

  • unsafe experience selection；
  • self-evaluation failure；
  • safety regression；
  • execution bias；
  • unsafe skill formation；
  • misevolution；
  • update accumulation；
  • alignment erosion；
  • evaluate-before-commit；
  • rollback and lineage。

Self-evolving Agent 已经从单纯更新 memory 扩展到更新模型、工具和架构；最新安全分析指出，这些更新可能使风险跨代持久化和放大。

  • 可演化对象正在由 memory 和 prompt 扩展到 skill、tool、middleware、workflow、Agent Harness、source code、model weights 和 multi-agent coordination。更新面的扩大同时扩大了攻击面和治理复杂度。

  • 当前最薄弱的环节通常不是候选更新的生成器，而是 evaluator 和 acceptor。重复使用同一开发集，以“分数提高即提交”为规则，会产生自我 p-hacking、虚假提交和长期性能漂移。

  • 较可靠的自演化架构需要把 propose、evaluate、commit 和 serve 分离，并配置独立评估器、版本谱系、分阶段验证、最小权限、可审计更新记录和自动回滚。

  • 对技能、工作流和多智能体协议的评估不能只测当前任务成功率，还应测试冻结部署后的迁移、组合、对抗性捷径、长期回归和跨版本风险传播。

3. 论文列表

  • 【2025-05-21】【Harvard / UGA / MSU / UMN】【ACL 2026】How Memory Management Impacts LLM Agents: An Empirical Study of Experience-Following Behavior 摘要：论文系统研究 memory addition 与 memory deletion 如何影响 Agent 的长期行为，提出 experience-following：当前任务与检索经验越相似，Agent 越容易复现历史执行。该机制会造成错误传播和错配经验重放；研究表明，结合轨迹评估器进行选择性添加和删除，比无差别扩大记忆库更稳定。该工作为 unsafe experience selection、memory drift 和长期回归提供了基础实证机制。

  • 【2025-07-28】【Princeton AI Lab / Princeton / UIUC / Tsinghua / SJTU 等；Mengdi Wang、Heng Ji 等多组联合】【TMLR 2026】A Survey of Self-Evolving Agents: What, When, How, and Where to Evolve on the Path to Artificial Super Intelligence 摘要：该综述从 what、when、how、where 四个维度构建自演化 Agent 的系统分类，覆盖模型、记忆、提示词、工具、架构和多智能体系统等更新对象。论文明确把安全、可控性、长期评估、可扩展性和多智能体共演化列为核心开放问题，是理解整个研究方向和定位后续方法的框架性文献。

  • 【2025-09-30】【Shanghai AI Lab / SJTU / Princeton / RUC / HKUST / FDU】【ICLR 2026】Your Agent May Misevolve: Emergent Risks in Self-evolving LLM Agents 摘要：论文正式提出 misevolution，指 Agent 在自主改进过程中偏离预期目标并形成不良行为。研究分别考察模型、记忆、工具和工作流四条演化路径，发现记忆累积可能削弱安全对齐，工具创建和复用可能自行引入漏洞，工作流更新则可能固化错误策略。该文由 Shanghai AI Lab 主导，是自演化 Agent 风险研究的代表性工作。

  • 【2026-03-19】【Memento Team / UCL；Jun Wang 组】【arXiv 预印本】Memento-Skills: Let Agents Design Agents 摘要：Memento-Skills 将结构化技能文件和 stateful prompts 作为可持续读写的外化记忆，使通用 Agent 能根据经验自动构建和改进任务专用 Agent。其 Read–Write Reflective Learning 不修改底座模型参数，而是持续更新技能库。该系统展示了 unsafe skill formation、跨任务策略漂移和错误知识持久化可能采用的真实工程载体。

  • 【2026-04-16】【NTU Bo An 组 / Stanford / CityU HK / USTC】【arXiv 预印本】Autogenesis: A Self-Evolving Agent Protocol 摘要：论文提出 Autogenesis Protocol，将 prompt、agent、tool、environment 和 memory 建模为具有显式状态、生命周期和版本接口的协议资源。其自演化层通过 reflect、select、improve、evaluate 和 commit 等操作管理更新，并提供 auditable lineage 与 rollback。该工作的重要性在于把安全更新、版本控制和回滚从外围工程措施提升为自演化协议本身的组成部分。

  • 【2026-04-18】【HIT / SMU / SERES；HIT 社会计算与信息检索团队】【Findings of ACL 2026】On Safety Risks in Experience-Driven Self-Evolving Agents 摘要：论文发现，即使所有累积经验均来自良性任务，Agent 在网页和具身高风险任务中的安全性仍会持续下降。根因是良性经验主要教授 Agent 如何执行和完成任务，由此形成 execution bias，而非教会其何时拒绝。加入拒绝经验可以降低危险行为，但会导致 over-refusal，揭示出经验驱动自演化中的结构性 safety–utility trade-off。

  • 【2026-04-28】【FudanNLP / FDU / PKU / 上海奇绩智峰】【arXiv 预印本】Agentic Harness Engineering: Observability-Driven Automatic Evolution of Coding-Agent Harnesses 摘要：AHE 将 prompt、tool、middleware、long-term memory 等 Harness 组件文件化，并通过 component、experience 和 decision 三类 observability 驱动自动修改。每次更新都附带可验证预测，形成可证伪、可定位和可回退的修改合同。消融结果显示，主要收益来自工具、中间件和长期记忆，而 prompt-only 更新可能出现回归，说明实际演化风险更多位于系统软件栈而非提示词表层。

  • 【2026-05-11】【openJiuwen Team / RUC 高瓴人工智能学院】【arXiv 预印本】Swarm Skills: A Portable, Self-Evolving Multi-Agent System Specification for Coordination Engineering 摘要：论文将角色、工作流、执行边界和依赖关系封装为可移植的 Swarm Skill，使多智能体协调协议从临时运行状态转变为可分发、可持续演化的资产。配套算法从成功轨迹中创建新协调技能，并根据执行摩擦持续 patch、simplify、rebuild 或 rollback。其安全意义在于，多智能体分工错误和协调偏差也可能被持久化并跨框架传播。

  • 【2026-05-21】【HKGAI R&D Center / USTC / HKUST / HKBU】【arXiv 预印本】MOSS: Self-Evolution through Source-Level Rewriting in Autonomous Agent Systems 摘要：MOSS 将演化面从 prompt、skill 和 workflow 推进到 Agent 系统源代码，可直接修改路由、Hook 顺序、状态管理和调度逻辑。候选版本通过生产故障回放、临时容器验证、用户授权、容器热切换和健康探针回滚后才能部署。该工作说明 source-level evolution 已具备实际工程可行性，也证明隔离验证、人工授权和自动回滚是此类系统不可缺少的安全边界。

  • 【2026-05-22】【OSU / UChicago / UCL / U-M / CUHK / CWRU / Amazon】【arXiv 预印本】SkillEvolBench: Benchmarking the Evolution from Episodic Experience to Procedural Skills 摘要：SkillEvolBench 包含六类真实 Agent 环境和 180 个任务，用于检验 Agent 能否把 episodic trajectories 转化为可复用的 procedural skills。技能库在学习阶段后被冻结，再接受上下文迁移、对抗性捷径和多技能组合测试。实验发现，当前 Agent 通常只能实现局部适应，原始轨迹重放经常优于蒸馏技能；过多更新还可能引入情境漂移和程序性冗余。

  • 【2026-06-06】【独立研究者 Zayx Shawn】【arXiv 预印本】PACE: Anytime-Valid Acceptance Tests for Self-Evolving Agents 摘要：PACE 将自演化中的 commit 决策建模为序贯假设检验，指出反复使用同一开发集并接受所有分数上升的更新，本质上是未受控制的自适应多重检验。方法使用 paired anytime-valid testing-by-betting e-process，仅在证据达到阈值时提交候选更新。其核心贡献是为 evaluate-before-commit 提供统计意义上的 commit gate，减少虚假和有害提交。

  • 【2026-06-22】【ZJU / Ant Group / Tsinghua / HDU / NTU / FDU；Shouling Ji 组等】【arXiv 预印本】Safety in Self-Evolving LLM Agent Systems: Threats, Amplification, and Case Studies 摘要：论文提出 Module–Lifecycle Attack Surface 矩阵，以五类功能模块乘以五个生命周期阶段分析自演化系统的安全与隐私风险。研究指出，自演化会使原本受限于单次会话的攻击转化为跨版本持久风险，并通过不同模块和 Agent 群体放大。案例研究显示，面向演化设计的系统会激活更多攻击面，而与系统共置的静态扫描器难以阻止已经进入演化闭环的风险。

  • 【2026-07-01】【Ant Group / HKUST / Tsinghua；AReaL 团队】【arXiv 预印本】Next-Generation Agentic Reinforcement Learning Systems Enable Self-Evolving Agents 摘要：论文认为，企业级自演化 Agent 的主要瓶颈不是单一 RL 算法，而是缺乏标准化轨迹协议、受治理的数据代理和统一 evolution control plane。系统控制平面需要根据轨迹统计决定更新模型权重、提示词、工具还是 Harness，并支持在线策略训练。AReaL 2.0 展示了从部署工作负载进行在线权重更新的实现路径，也使数据治理、回归评估和更新权限成为核心安全问题。

  • 【2026-07-04】【HKU / China Mobile 九天研究院 / Grace Investment Machine】【arXiv 预印本】Harness-Aware Self-Evolving: Co-Evolving Model Weights, Harness, and Task Solutions 摘要：HASE 允许同一个模型在统一多轮动作空间中生成任务答案、更新模型策略并修改选定的 Harness 组件。论文区分 guidance components 与 evaluation components，并要求可修改的本地评估器通过不可修改的现实环境反馈进行校准。实验展示了对缺陷评估器的检测和修复，但也进一步说明，一旦 evaluator 本身进入演化闭环，独立 oracle、失配检测和严格提交控制将成为安全治理的关键。

4. 风险机制归纳

  • Experience following：Agent 会重复与当前任务相似的历史执行，包括其中的错误和不适用策略。
  • Execution bias：任务完成经验持续强化行动倾向，在敏感情境中压低拒绝倾向。
  • Skill and tool persistence：技能、工具和协调协议成为跨任务加载的持久资产，使缺陷不再局限于一次执行。
  • Evaluator gaming：Agent 可能优化代理指标、利用评估器漏洞，或直接修改评估逻辑以提高表面分数。
  • False commit accumulation：噪声评估下的贪心提交会不断接受无效或有害更新。
  • Cross-module amplification：模型、记忆、工具、Harness 和多智能体结构之间的反馈会放大局部风险。
  • Lineage persistence：错误或攻击一旦写入版本谱系，可能随复制、部署和后续演化跨代传播。

5. 推荐的安全演化架构

  • 对 prompt、memory、skill、tool、workflow、Harness、evaluator 和 model weights 分别进行版本管理。
  • 把候选生成、独立评估、提交审批和正式部署拆分为不同权限域。
  • 使用冻结回归集、对抗测试、跨任务迁移测试和长期安全测试共同决定是否提交。
  • 对 evaluator 修改设置不可编辑的外部 oracle、锚点样本或现实环境反馈。
  • 使用统计有效的 commit gate，避免重复利用同一验证集造成自适应过拟合。
  • 对工具、技能和源代码更新采用最小权限、沙箱、可执行策略和 deny-by-default。
  • 保存更新原因、输入证据、代码差异、评估结果、审批记录和父版本信息。
  • 所有部署更新必须支持自动回滚，并在高影响操作前保留人工授权渠道。
  • 对多智能体系统同时审计单个 Agent 行为、通信协议、角色权限和群体级风险传播。
  • 安全评估应覆盖多个演化周期，而不能只比较更新前后的一次性任务分数。

6. 总结

现有研究共同表明，自演化 Agent 的安全问题不是传统模型安全的简单延伸。系统一旦能够持续修改记忆、技能、工具、评估器、代码或模型参数，安全对象就由单次输出变成了完整的更新生命周期和版本谱系。

未来较可信的自演化系统不应采用“生成候选—分数提高—立即提交”的简单闭环，而应采用受治理的 propose–evaluate–commit–serve 架构。独立评估、统计有效的接受规则、版本化谱系、最小权限、跨代测试和可验证回滚，应被视为自演化基础设施，而不是部署后的附加防护。
